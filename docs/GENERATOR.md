# README generator

The generator selects one random tarot card and writes `README.md` from a template.
It is a Node.js command-line program in TypeScript. The source is in [`src/`](../src).

## Commands

| Command                  | Result                                                          |
| ------------------------ | --------------------------------------------------------------- |
| `npm run readme`         | Build the program, select a card, and write `README.md`.        |
| `npm run readme:dry-run` | Build the program and print the new `README.md`. Write no file. |
| `npm test`               | Build the program and run the Vitest tests.                     |

The commands use the current directory as the repository root. Run them from the root.

## Cards

A card is a text file and an image file with the same name in [`assets/`](../assets), for example `The Fool.md` and `The Fool.png`.

| Item            | Rule                                                                                   |
| --------------- | -------------------------------------------------------------------------------------- |
| Text file       | `.md` or `.txt`, UTF-8, not empty, at most 16 KiB. The text is Markdown.               |
| Image file      | `.png`, `.jpg`, `.jpeg`, `.webp`, `.gif`, `.avif`, or `.svg`.                          |
| Card name       | The file name without the extension. Letters, digits, spaces, and `' ’ . , ( ) & _ -`. |
| Name comparison | Letter case is ignored. The two files can be in different subdirectories of `assets/`. |
| Ignored files   | Hidden files, symbolic links, and other file types.                                    |

A text file without an image, or an image without a text, is not a card. The program shows a warning for each such file and continues.
The program stops with an error when two files of the same type have the same card name, a text is empty, or no complete card exists.

Use PNG for card images, so that all cards have the same format.

To add a card:

1. Add the text file and the PNG image with the same name.
2. Add the card to [LIST.md](../LIST.md) by hand. This page shows all cards with their texts for a manual check.
3. Run `npm test` and `npm run readme:dry-run`.

## Template

The template is [`templates/README.template.md`](../templates/README.template.md). It is Markdown with placeholders.
A placeholder is an HTML comment, so the template stays valid Markdown.

| Placeholder            | Replaced with                                           | Occurrences  |
| ---------------------- | ------------------------------------------------------- | ------------ |
| `<!-- tarot:image -->` | An `<img>` element with the card image and a cache key. | Exactly one. |
| `<!-- tarot:text -->`  | The card text.                                          | Exactly one. |
| `<!-- tarot:name -->`  | The card name.                                          | Any.         |
| `<!-- tarot:date -->`  | The date in Amsterdam, for example `5 November 2026`.   | Any.         |

The program rejects an unknown `tarot:` placeholder and a wrong number of occurrences.
All placeholders are replaced in one pass. A placeholder in a card text is not replaced.
All other template text stays the same in `README.md`.

The `<img>` element sets only the width (300 pixels). The browser calculates the height from the image proportions, so that images of different sizes have the same width and are not distorted.

The image link has a random cache key in the query string, for example `assets/The%20Fool.png?v=3f9a1c0e7b2d4a61`.
Each run makes a new key, so that browsers and the GitHub image proxy show the new image and do not use an old copy.

## Generated README

The first line of `README.md` is an HTML comment. It identifies the template and the card, for example:

```md
<!-- Generated by `npm run readme` from templates/README.template.md. Do not edit this file. Edit the template. Card: The Fool -->
```

The next run reads this line and does not select the same card again, so the reading changes each day.
Do not edit `README.md`. The next run replaces it.

## Security

| Boundary     | Control                                                                                        |
| ------------ | ---------------------------------------------------------------------------------------------- |
| Card files   | Size limit, UTF-8 check, name check, and HTML escaping of the name and the image path.         |
| Asset search | No symbolic links, depth and entry limits, and no paths outside `assets/`.                     |
| Template     | Placeholder check before the write. Card text cannot add placeholders.                         |
| Output       | Only `README.md` is written. The write is atomic. The program refuses to write through a link. |
| Randomness   | `crypto.randomInt` from Node.js.                                                               |
| Network      | The program has no network access.                                                             |

The card texts are Markdown and go into `README.md` without changes. GitHub sanitizes HTML in `README.md`.
Review a change to the card texts as a change to the page.
